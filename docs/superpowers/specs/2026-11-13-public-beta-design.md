# RepeatScope public Beta

The user authorized version integration and public Beta deployment on 2026-11-13, with numerical accuracy as the release gate and questions only when account access or user action is required.

Preserve v1.11.1 scientific algorithms and all original research inputs. Integrate PRs 1 and 2 and the deployment changes after verification. Keep the GitHub repository private and all research data local. Publish a code-and-synthetic-only application on Posit Connect Cloud using rsconnect direct upload. Sites cannot host an R process; a container host would add unnecessary infrastructure. Connect Cloud is the chosen default, subject to the user's existing host preference.

The deployment must have an entry point that finds the nested Shiny app and its shared algorithms without Windows paths. Package only explicitly reviewed runtime paths. Resolve package dependencies from the verified library and record versions. Never upload tests, QA results, saved projects, local libraries or credentials.

Public visitors start with an empty session or the clearly labelled synthetic example. Explain that uploads are processed on the hosting server, sessions are temporary and Save project is needed. Keep research-preview and formal-QC distinctions. Do not expose raw research projects for online acceptance testing.

Release gates: existing synthetic R and JavaScript suites, unchanged scientific source hashes, local private-data numerical comparisons for both methods/windows, packaged-app startup and synthetic numeric acceptance, session isolation, save/restore/download checks, independent review, then cloud synthetic/browser acceptance. Any real numerical mismatch blocks release. Computational agreement is not a claim of biological validation.

Account login is performed by the user. No paid plan or public source repository is required by this design. Record any host limitation before committing expenditure or changing source visibility.
